# Better Captions 0.7.8 — Mac verification

The listed installed checks completed in Premiere Pro 26.5.2 on macOS as of 2026-10-17. This is a development prerelease with the acceptance limits below, not a claim that every feature is verified. Timeline changes used dedicated verification fixtures. Human-authored Motion was read before and after a deliberately rejected legacy conversion to confirm protection. Personal project paths and private media are omitted.

Completed native core checks in this record used the 0.7.6 development build; that core source is retained in 0.7.8. Adobe's same-version 0.7.6 reinstall reported success without replacing the UXP track helper, so its repeated old lookup error did not evaluate the replacement. The unique, byte-verified 0.7.7 installation loaded the new lookup but returned `Invalid parameter.` without a native phase. Version 0.7.8 adds the documented generic `ProjectItem` cast before insert Action creation and bounded phase/context diagnostics. Its new-track acceptance passed after all 23 checked installed files were independently matched before launch. This is evidence of the successful corrected flow, not proof of the exact cause of the earlier generic error.

The installed-host failures found during acceptance were corrected before the successful final Apply: file-path validation no longer uses the regex syntax that aborted ExtendScript loading; the readiness handshake publishes the verified bridge globally and checks it from a separate evaluation; and Motion/geometry timing uses explicit branches instead of the nested conditional expression that dereferenced a null fragment fallback. The Motion reader retains bounded phase, frame and native line diagnostics.

The first new-track attempt stopped before timeline mutation because the original opaque media-path search reported the imported seed missing or ambiguous. The exact reason for that API result is not established. Setup now enumerates the project root and generic folder children using the documented [Project.getRootItem](https://developer.adobe.com/premiere-pro/uxp/ppro-reference/classes/project) and [FolderItem.cast/getItems](https://developer.adobe.com/premiere-pro/uxp/ppro-reference/classes/folderitem) APIs. The lookup is bounded to 2,000 items, 256 folders and depth 32; it requires one exact local media-path match and classifies sequences before requesting filesystem paths. Missing, ambiguous, malformed or unreadable identities fail before Action creation, with bounded lookup counts. The insert Action receives [ProjectItem.cast](https://developer.adobe.com/premiere-pro/uxp/ppro-reference/classes/projectitem)'s generic wrapper, as required by [SequenceEditor.createInsertProjectItemAction](https://developer.adobe.com/premiere-pro/uxp/ppro-reference/classes/sequenceeditor). All Action factories remain synchronous inside locked access; insert/removal flags and exact setup-clip ownership checks are retained.

The final read-only saved-project audit passed after the 0.7.8 checks. All three production sequence graphs were equal after documented serialization normalization: expanding object references, ignoring numeric serialization IDs, sorting `Properties` map entries, and excluding `MasterClipChangeVersion` save counters. Both protected Verification Motion clips retained their existing identities and timing; all 22 Motion parameter records retained their values, key times, interpolation fields and tangents, with only cosmetic parameter names omitted from that comparison.

The four fixture V1/A1 source-track graphs also matched after their explicitly documented scalar-field ordering and newly persisted ID normalization; existing IDs were retained in the comparison. Both saved test-fixture V2 caption bundles had no remaining test Motion keys. All 54 absolute and 54 resolved relative media references existed, with no temporary references. All 16 foreign dirty checkout files and the preset file bytes were unchanged. The saved project stayed unchanged during the audit. This proves the recorded saved-file state, not unsaved application state or playback behavior. The final receipt is `subagent-saved-project-preservation-final.json`; it retains the precise normalization rules and original graph deltas.

Final source checks after the typed insert wrapper and phase diagnostics completed with `npm test`: 527 total tests, 525 passed, no failures, and two Windows-only tests skipped on Mac. `npm run check` reported zero errors and zero warnings. These checks are separate from installed Premiere acceptance.

The plugin's Width key operations, Undo and Redo completed the native checks above, and its temporary Width and Height animation could be toggled off. Removing the test Position animation was refused before mutation because Premiere does not expose the Point key interpolation needed to prove exact Undo. Existing opaque/custom native Position easing remains protected: moving or removing such keys requires Premiere's Effect Controls when the API cannot preserve and verify the curve. Numeric value edits can still use the in-place key setter. The rejection is not a passed Position-animation removal test and the guard is not relaxed for cleanup.

Acceptance limits:

- **Physical dragging is not accepted.** Both the primary operator and an independent UI tester displayed the blue native transform handles, but their Computer Use drag attempts produced no confirmed native Position or size change. The automation result is unresolved. Visible handles, successful numeric edits and keyframe readback do not establish mouse-drag behavior.
- Compatible static legacy multi-clip conversion was not accepted natively in this run. The verified refusal of animated legacy clips and passing source tests do not establish successful native conversion.
- Windows installed acceptance remains blocked by Adobe installation. Mac results do not establish Windows behavior.

Completed native results and the unresolved limits are recorded separately so the source-test count is not mistaken for complete feature acceptance.
